💡 核心发现

🔴 出货与扫码严重脱节

河南（5.9万箱 / 5.8%）、山东（5.6万箱 / 5.9%）出货量大但扫码极低——货出去了，终端没扫。这两个省合计 11.5 万箱几乎未动销。

🟡 一部二部差距悬殊

TOP5 办事处全在一部，BOTTOM5 全在二部。不是个别办事处的问题，是系统性差异。二部的扫码激励机制或执行力度可能需要整体审视。

🟢 90天消化停摆规律成立

12月批次：90天达 32.2% → 120天达 38.5% → 最终 41.6%。出货后 3 个月是黄金扫码期，之后增速骤降。跟汉老师经验"最多 40%"完全吻合。

🟢 出厂到终端全链路 ~2 个月

工厂出库 → 经销商提货 ~25天 → 终端扫码消化 ~35天 = 完成动销反馈共约 60天。12月出的货，2月才开始规模化扫码。

🔬 方法论与 SQL

动销率计算逻辑与踩坑记录

数据源：ai_merchants_str（工厂出货 + 终端扫码）

关键陷阱：表中 548,472 条未扫码行 inner_qrcode = NULL，导致 COUNT(DISTINCT inner_qrcode) 只数到已扫码箱（296,426），动销率错误显示为 100%。

正确公式：

动销率 = COUNT(DISTINCT 已扫码 inner_qrcode) / (COUNT(DISTINCT 已扫码) + COUNT(未扫码行))
= 294,948 / (294,948 + 548,472) = 35.0%
SQL：按出货月动销率 
SELECT 
  CASE WHEN scan_time IS NOT NULL THEN '已扫码' ELSE '未扫码' END AS status,
  out_month,
  COUNT(*) AS rows,
  COUNT(DISTINCT IIF(scan_time IS NOT NULL, inner_qrcode, NULL)) AS scanned_boxes
FROM ai.ai_merchants_str
WHERE out_month BETWEEN '2025-12' AND '2026-04'
GROUP BY CASE WHEN scan_time IS NOT NULL THEN '已扫码' ELSE '未扫码' END, out_month
ORDER BY out_month, status
SQL：按办事处动销率 
WITH base AS (
  SELECT 
    org_name,
    IIF(scan_time IS NOT NULL, 1, 0) AS is_scanned,
    inner_qrcode
  FROM ai.ai_merchants_str s
  JOIN ai.ai_shop_info i ON s.shop_code = i.shop_code
  WHERE i.status = 'ZT001'
)
SELECT 
  org_name,
  COUNT(DISTINCT IIF(is_scanned=1, inner_qrcode, NULL)) AS scanned,
  COUNT(DISTINCT IIF(is_scanned=1, inner_qrcode, NULL)) + SUM(IIF(is_scanned=0,1,0)) AS total,
  CAST(COUNT(DISTINCT IIF(is_scanned=1, inner_qrcode, NULL))*100.0 /
    (COUNT(DISTINCT IIF(is_scanned=1, inner_qrcode, NULL)) + SUM(IIF(is_scanned=0,1,0))) AS DECIMAL(5,1)) AS rate
FROM base
GROUP BY org_name
ORDER BY rate DESC
